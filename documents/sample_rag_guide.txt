RAG (Retrieval Augmented Generation) Architecture Guide

What is RAG?
RAG is a technique that enhances Large Language Models (LLMs) by giving them access
to external knowledge. Instead of relying only on training data, the LLM can search
through your documents to find relevant information before generating a response.

Why RAG?
1. Up-to-date information: LLMs have knowledge cutoffs. RAG provides current data.
2. Domain-specific: Your documents contain proprietary knowledge the LLM doesn't have.
3. Reduced hallucination: The LLM answers from facts, not imagination.
4. Cost-effective: Cheaper than fine-tuning a model on your data.
5. Verifiable: You can see exactly which sources were used.

RAG Pipeline Steps:
1. DOCUMENT LOADING: Read documents (PDF, text, markdown, etc.)
2. CHUNKING: Split documents into smaller pieces (typically 500-1500 characters)
3. EMBEDDING: Convert text chunks into numerical vectors using an embedding model
4. INDEXING: Store vectors in a vector database (ChromaDB, Pinecone, etc.)
5. QUERYING: When a user asks a question:
   a. Convert the question to a vector
   b. Search the vector database for similar chunks
   c. Pass the retrieved chunks as context to the LLM
   d. LLM generates an answer based on the context

Chunking Strategies:
- Fixed size: Split every N characters (simple but may break sentences)
- Recursive: Try paragraph breaks first, then sentences, then words
- Semantic: Use an LLM to identify natural topic boundaries
- Overlapping: Include some text from the previous chunk for context

Embedding Models:
- text-embedding-005 (Google): Latest Google embedding model
- text-embedding-ada-002 (OpenAI): Popular OpenAI embedding model
- Sentence Transformers: Open-source alternatives

Vector Databases:
- ChromaDB: Local, open-source, great for prototyping (used in this project)
- Pinecone: Cloud-hosted, scalable
- Weaviate: Open-source with cloud option
- Qdrant: Open-source, high performance

Production Considerations:
- Chunk size tuning: Too small = missing context; too large = noise
- Overlap: 10-20% overlap prevents losing context at boundaries
- Metadata filtering: Filter by source, date, category before similarity search
- Reranking: Use a cross-encoder to rerank results after retrieval
- Caching: Cache frequent queries and their results
- Monitoring: Track retrieval quality, latency, and user satisfaction

MCP (Model Context Protocol):
MCP is a standard protocol for connecting AI models to external data and tools.
By exposing our RAG pipeline as an MCP server, any MCP-compatible AI assistant
(like Claude) can use our document search capabilities.

Google ADK (Agent Development Kit):
Google ADK allows building AI agents that can use tools. An agent decides
when and how to use tools based on the user's question. Our agent uses
the RAG pipeline as one of its tools.
